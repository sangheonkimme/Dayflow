## 1. 제품 현황 진단

현재 Dayflow는 **"개인 일상 운영 올인원"** 포지션. 코드베이스 기준 보유 기능 4축:

| 축 | 기능 | 비고 |
|---|---|---|
| 가계부 (머니) | 거래 기록(ledger/txns), 영수증 업로드, 구독 관리(subs), 머니플로우 | 결제 의향 검증된 카테고리 |
| 일정·생산성 | 캘린더, 메모, 스티키노트, 체크리스트, 타이머 3종 | 대체재 강함 (구글캘린더·노션) |
| 금융 유틸리티 | 연봉 계산기, 대출 검색 | 비로그인 SEO 유입구 + 제휴 수익 후보 |
| 범용 유틸리티 | 이미지 크롭, PDF 편집 | 비로그인 트래픽 유입구 |

기반: Supabase 인증 + RLS, mock/supabase 전환 가능한 3-tier 데이터 레이어, PC/모바일 분리 UI,
모바일 `UpgradeSheet.tsx`에 **Dayflow Pro 시안 완비** (₩3,900/월 · ₩39,000/년 · 3일 무료 체험).

- **강점**: 유입(무료 도구) → 정착(가계부·일정) → 과금(Pro) 퍼널의 뼈대가 이미 코드에 존재.
- **약점**: 축이 4개라 "무엇의 앱인지" 흐릿함. 수익화 전에 핵심 축 하나를 리텐션 엔진으로 세워야 함.

### 핵심 제언 — 가계부(머니) 축을 메인으로

일정·메모는 대체재가 너무 강하지만, "구독 관리 + 명세서 import + 머니플로우"는 한국 시장에서
결제 의향이 검증된 카테고리(뱅크샐러드·편한가계부 등). 타이머·메모·캘린더는
**"머니 앱에 딸려오는 보너스"**로 포지셔닝하고 유지보수만, 신규 투자는 머니 축에 집중한다.

### 웹 서비스 제약 (기능 채택 잣대)

기능 검토 시 아래 제약을 통과해야 채택. v1.1 개정의 근거이기도 함.

- **카메라·SMS·위젯 등 디바이스 밀착 기능은 웹에서 반쪽**: 영수증 스캔, 카드 SMS 파싱, 잠금화면 위젯은 네이티브 앱 영역. 웹은 **파일 업로드·일괄 처리·큰 화면**이 강점 — 기능도 이 방향으로 설계.
- **웹푸시는 iOS Safari 에서 PWA 설치 후에만 동작**: 알림류 기능은 이메일 병행이 기본, 웹푸시는 보조.

## 2. 추가 기능 로드맵

### Phase A — 과금 근거 만들기 (1~2개월, 기존 데이터 레이어로 구현 가능)

| 우선순위 | 기능 | 내용 | 구현 난이도 |
|:---:|---|---|---|
| ★★★ | **카드·은행 명세서 import (CSV/엑셀)** | 카드사·은행 내역 파일 업로드 → 거래 일괄 등록. 파일 업로드는 PC 웹이 네이티브 앱보다 강한 영역. 카드사별 포맷 매핑 테이블로 시작 | 중 — 파서 + 중복 감지 + 매핑 UI. API 비용 0원. **Pro 앵커 1순위** |
| ★★★ | 예산 설정 | 카테고리별 월 예산 + 초과 경고, MoneyFlow에 진행률 표시 | 하 — 도메인 1개 추가 (기존 8개 도메인 패턴 그대로) |
| ★★★ | 반복 거래 | 월세·구독료 자동 기입. 구독 도메인 ↔ 거래 도메인 연결 | 하 |
| ★★ | 구독 결제일 알림 | 결제 D-3/D-day 알림. subscriptions 도메인에 결제일 이미 존재. **채널은 이메일 우선** (Supabase Edge Function + cron), 웹푸시는 보조 | 중 |
| ★★ | 빠른 입력 UX | "점심 9500" 자연어 한 줄 파싱 + 자주 쓰는 거래 템플릿. 기록 마찰을 줄이는 가장 싼 방법 | 하 — 정규식/경량 파서로 시작 |
| ★★ | 월간 리포트 | 카테고리별 지출 요약·전월 대비·구독 합계. UpgradeSheet에 이미 "월간 PDF 리포트"로 약속됨 | 하 — transactions 집계 + RSC 페이지, PDF는 기존 pdf 도구 코드 재활용 |

> **기존 `ReceiptUploadModal` 처리**: OCR 없이 **거래에 증빙 사진 첨부(보관)** 용도로 강등 유지.
> 이미 구현돼 있어 추가 비용 없고, 네이티브 앱 출시 시 OCR 을 얹을 자리가 됨.

#### 검토 메모 — 영수증 OCR 을 제외한 이유 (2026-06-12)

1. **캡처 동선 부재**: PC 웹에선 종이 영수증을 폰으로 찍어 옮겨야 해 동선이 끊김. 모바일 웹 `<input capture>` 는 연속 스캔·오프라인 큐가 안 돼 "가끔 한 장" 수준. 영수증 스캔이 돈이 되는 곳은 경비 정산 B2B SaaS 지 B2C 가계부가 아님.
2. **수요 자체가 감소**: 지출 대부분이 카드·간편결제. 사용자의 진짜 페인은 "카드 내역 옮기기"이고, 정답은 영수증 사진이 아니라 **거래 내역을 직접 가져오는 것** → 명세서 import 로 대체.
3. **비용 대비 품질**: 한글 영수증 OCR 정확도가 애매해 수정 UI 필수 + 건당 API 비용 지속 발생. Pro 결제 이유로 내세웠다가 품질 불만이 해지 사유가 되는 역효과 패턴.

### Phase B — 리텐션 엔진 (3~5개월)

| 우선순위 | 기능 | 내용 |
|:---:|---|---|
| ★★ | 주간 인사이트 알림 | "이번 주 외식비가 평소보다 40% 많아요" — daily-log 도메인 활용. 가계부 리텐션의 핵심은 기록 알림이 아니라 **인사이트 알림**. 채널: 이메일 기본 + 웹푸시 opt-in |
| ★★ | 자동 카테고리 분류 | 명세서 import 시 가맹점명 → 카테고리 자동 매핑(규칙 + 사용자 학습). **Pro 차별화 기능** — import 자체는 무료여도 분류 자동화가 결제 이유 |
| ★★ | 데이터 내보내기/가져오기 | CSV·엑셀. 전환장벽 제거(타 가계부에서 이사 오기) + Pro 잠금 포인트(내보내기 무료, 자동 백업 Pro) |
| ★★ | 홈 모듈 커스터마이징 | 홈 6개 모듈(StickyNotes/Checklist/MoneyFlow 등) 켜고 끄고 배치 — preferences 스토어에 유사 토글(`showCalendar`) 기존재. Pro 시안의 "테마·위젯 잠금 해제"와 연결 |
| ★ | 공유 가계부 (커플·룸메이트) | RLS 구조상 `household_id` 도입으로 확장 가능. 결제 전환률 높은 기능이나 스키마 영향 커서 B 후반 |

### Phase C — 확장 (6개월+, PMF 확인 후)

| 우선순위 | 기능 | 비고 |
|:---:|---|---|
| ★ | 계좌·카드 연동 | 오픈뱅킹/마이데이터 제휴 or 스크래핑. 비용·규제 부담 큼. 명세서 import 사용률이 높으면 그게 수요 증거 → 그때 투자 판단 |
| ★ | 영수증 OCR | **네이티브 앱(또는 PWA 카메라 UX 확보) 출시 시 재검토.** 웹 단독에선 채택 안 함 — §2 검토 메모 참고 |
| ★ | 커뮤니티 | 절약 챌린지·지출 인증. 리텐션엔 좋지만 운영 비용 큼 → MAU 확보 후 |

**결제 수단**: 웹 우선이므로 **토스페이먼츠 빌링(정기결제)** 권장 — 국내 카드 정기결제 + 구현 단순.

### 3-3. 전환 퍼널

```
SEO 유입 (크롭 · PDF · 연봉계산기 · 대출검색, 비로그인)
  → 도구 결과 저장/기록 유도 시점에 회원가입 (Google OAuth 기구현, 마찰 최소)
  → 가계부·구독 기록 습관화 (D7 리텐션 = 인사이트 알림)
  → Pro 트리거 노출: 명세서 import 한도 도달 / 자동 분류 미리보기 / 월간 리포트 발송일 / 광고
  → 3일 체험 → 연간 플랜 유도 (17% 할인 배지, 기존 시안대로)
```

> 핵심 트리거는 **"import 한도 + 자동 분류 미리보기"** — 무료 사용자가 import 한 내역에
> "Pro 라면 이렇게 자동 분류돼요" 미리보기를 보여주는 것이 가장 자연스러운 페이월 접점.

## 4. 실행 우선순위 및 KPI

### 실행 순서 (수익까지의 거리 기준)

1. ★★★ 대출·연봉 페이지 제휴 링크 부착 — 개발 1주 내, 즉시 수익
2. ★★★ 예산 + 반복 거래 — 리텐션 기반 (도메인 패턴 재사용, 빠름)
3. ★★★ 명세서 import (주요 카드사 3~4곳 포맷부터) — Pro 앵커
4. ★★ 월간 리포트 + 결제일 알림(이메일) — Pro 가치 보강
5. ★★ 토스페이먼츠 빌링 연동 + UpgradeSheet 실결제 wire-up
   (PC용 업그레이드 모달 신규 필요 — 현재 시트는 모바일 전용. 카피 수정 4건 동시 반영)
6. ★★ 자동 카테고리 분류 + 인사이트 알림 → 전환 퍼널 완성

### KPI

| 지표 | 목표 |
|---|---|
| 도구 페이지 → 가입 전환율 | 3~5% |
| D7 리텐션 (가계부 기록 유저 기준) | 25%+ |
| 명세서 import 사용률 (가입 30일 내) | 20%+ — 낮으면 Pro 앵커 재검토 신호 |
| 무료 → 체험 전환율 | 5% |
| 체험 → 유료 전환율 | 40%+ (3일 체험은 짧아서 높게 나오는 편) |
| 제휴 클릭 RPM | 측정 후 베이스라인 설정 |

### 리스크

- 4개 축을 동시에 키우면 전부 어중간해진다. 타이머·메모·캘린더는 유지보수만, 신규 투자는 머니 축에 집중.
- **명세서 import 는 카드사 포맷 변경에 취약** — 포맷 매핑을 데이터로 분리해 핫픽스 가능하게 설계. 파싱 실패 시 수동 매핑 fallback UI 필수.
- 명세서 import 사용률이 KPI 미달이면 "기록 자동화" 수요 가설 자체를 재검증 (그 경우 빠른 입력 UX 강화로 선회).
