# Dayflow UX/기능/코드 감사 — 모바일 vs PC

> 작성일: 2026-07-11 · 상태: 관찰 전용 (코드 변경 없음, 커밋 X)
> 스코프: 모바일 5개 화면·PC 8개 대시보드·공통 인프라
> 참고: `docs/settings-revamp-plan.md`, `docs/monetization-plan.md`, `docs/nextjs-migration-plan.md`

## 0. 총평

Phase 0~6 (Next 마이그레이션·CSS 모듈·`@ts-nocheck` 회복) 이 끝나 **뼈대는 튼튼한 상태**. 다만 UX 완성도는 축별로 편차가 크다.

- **PC (데스크톱)** — Settings 8섹션 중 Profile/Appearance(일부)/Ledger(월급일)/Data(내보내기)/Security(비밀번호) 5개만 실동작. 나머지는 `comingSoon` 뱃지로 정직해졌지만 **여전히 노출량이 많다.** 데이터 축(txns/subs/memo/calendar/ledger)은 완성도 우수, 인프라(RSC prefetch·Client 경계)도 안정. 실질 문제는 (a) 죽은 컨트롤, (b) Topbar 하드코딩, (c) 관측·최적화 부재.
- **모바일** — UI 시안은 예쁘지만 **데스크톱 데이터 레이어와 이원화가 심각**. `SubscriptionsScreen`은 목데이터, `NotificationsScreen`은 로컬 state, `ProfileScreen`은 하드코딩 stats, `titleByTab.ledger = "11월의 흐름"` 고정. **Theme 는 다크/액센트만 usePreferences 연결됐고 폰트·글자크기·간격은 로컬 state.** 세이프 에어리어·PWA·가상 키보드 대응이 전무.
- **우선순위 요약** — 모바일 쪽 "실데이터 연결"과 "세이프 에어리어/PWA" 가 신뢰 회복 축, PC 쪽은 "Settings comingSoon 축소 + Topbar 하드코딩 제거 + 결제 흐름 착수" 가 다음 라운드.

## 4. 다음 스프린트 착수 권장 Top 3

1. **모바일 데이터 이원화 정리 (M1~M4, M10)** — Ledger 헤더·Subs 화면·Notifications·Profile·Menu 카피를 실 데이터 훅으로 갈아끼움. 4~5일. 신뢰도 급상승, 감각적으로도 "모바일이 뒤쳐진다" 인상 제거. 데스크톱 이미 있는 셀렉터 재사용이라 리스크 낮음.
2. **세이프 에어리어 + PWA 기본 (M6, M7, M8)** — `env(safe-area-inset-*)` 도입, `100dvh`, `viewport-fit=cover`, `interactiveWidget=resizes-content`, `app/manifest.ts` 추가. 2~3일. **Pro 웹푸시(monetization-plan) 의 iOS 조건 을 만족시키는 선행 작업.** 홈스크린 추가 도입의 첫걸음.
3. **관측 + 결제 인프라 씨앗 (C2, C3, P6)** — Sentry `@sentry/nextjs` 붙이고, Toss 또는 LemonSqueezy 결제 webhook 스킴을 스파이크. 완성 결제 흐름까지 안 가도 `plan` 컬럼과 upgrade 라우트만 뚫어도 monetization-plan Phase A 착수의 시작점. 3~4일. **수익 실험을 시작해야 다음 라운드 우선순위 판단 근거가 생김.**

> 위 세 축은 서로 독립적이라 병렬 진행 가능. 인원이 1명이면 1→2→3 순서 권장 (신뢰 → 모바일 완성 → 수익).
